# 学习闭环路线图（总览）

日期：2026-07-20
状态：已批准方向（用户选定 #1/#2/#3/#5/#6 并确认推进顺序）

## 愿景

把 CourseAI 从「带 AI 面板的播放器」升级为「一门课的掌握系统」，四环飞轮：

**获取（批量导入）→ 理解（就地追问 + 跨视频提问）→ 留存（间隔重复）→ 追踪（仪表盘）**

仪表盘再把「今天该复习」「最弱主题」推回用户，驱动下一轮。

## 两个共享底座

- **学习事件日志**：一张 SQLite 事件流水表，记录观看会话与复习记录。
  仪表盘统计（#5）与间隔重复排期（#2）都建立在它之上。见
  [study-event-log](2026-07-20-study-event-log-design.md)。
- **概念/主题层**：AI 给字幕片段打概念标签。让课程检索变「概念定位」、
  卡片按概念成组、仪表盘能显示薄弱概念。作为 #1 的 P3 引入、被 #2/#5 复用。

## 推进顺序与理由

1. **学习事件日志**（底座，急）——#5 与 #2 都要它，先攒数据。
2. **#6 就地追问**——最轻、见效最快，纯复用 RAG 的 context，几乎不碰后端。
3. **#3 本地文件夹批量导入**先行（零成本），再做网络播放列表导入。
4. **#1 课程级 RAG**——复用检索管线，主要改作用域与跨视频引用。
5. **#2 间隔重复**——最重、留存价值最高，等 #1 概念层就绪一起做。
6. **#5 仪表盘**——等事件日志攒了数据再做，顺带接入 #2 待复习与薄弱主题。

## 依赖图

```
事件日志 ──┬─> #5 仪表盘（完成度/时长/连续天数）
           └─> #2 间隔重复（复习排期 review_logs）
#1 课程级RAG ──概念层──┬─> #2 卡片按概念成组
                       └─> #5 薄弱主题
#6 就地追问：独立，复用 RAG context
#3 批量导入：独立，复用处理队列
```

## 贯穿原则

- 全本地、无遥测；数据进 SQLite（迁移顺延编号），前端 `ipc.*` 包装。
- 复用既有：处理队列（jobs.rs）、RAG 检索（rag.rs）、出题/字幕管线、
  usePlayer 进度、resumeState 模式。
- 每个特性单独 TDD + 提交；只改自己的文件。
